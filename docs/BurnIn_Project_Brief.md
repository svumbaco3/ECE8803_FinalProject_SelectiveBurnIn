## 4\. Datasets

## 5\. Problem statement

Burn-in is expensive. Latent defects (dies that pass wafer test but fail burn-in) are rare and cluster near visible wafer-level failures. Train a model that assigns a burn-in risk score to every die that passed wafer test; burn in only dies above a threshold; quantify cost saved vs. latent defects caught.
Wafer-test ↔ burn-in data is proprietary, so: **parametric data = Gaussian values on the KAI die grid (synthetic); defect patterns = WM811K (real); burn-in labels = our simulator.**

## 7\. Final plan

### Step 1 – Simulator (runs before any training; fixed seed; all knobs in one config)

Development runs on the 10-wafer/lot subset (decision 18); final results on all 200 wafers/lot.

1. **Limits:** per parameter, from **Lots 1–4 only, before injection**: **mean ± 6σ** (multiplier configurable). Same limits applied to Lot 5. Report the natural (pre-injection) fail rate (expected ≈ 0).
2. **Overlay:** for each KAI wafer, sample a WM811K pattern (incl. some "none"), scale to the KAI grid, random rotation and placement, giving a cluster mask.
3. **Wafer-Test Fails:** 30–60% of in-cluster dies get a random subset of channels pushed **outside** limits; plus \~0.5% random isolated fails wafer-wide (natural fails ≈ 0).
4. **Simulator risk map (hidden):** for each passing die, p = base × m(d); base ≈ 0.002–0.005; m = 10 inside/touching the cluster, decaying to 1 over a few die-widths. Tune so **\~1–2% of passing dies** become latent defective.
5. **Latent Defective:** Bernoulli(p) per passing die.
6. **Clues:** 60–80% of Latent Defective dies get a random subset of parameters shifted 1–3σ (σ = that parameter's std), **staying inside limits**. The remaining 20–40% are unclued; they can still be caught by location, but isolated ones are uncatchable. This sets a **recall ceiling**; report it, and treat 100% recall as a sign of leakage.

### Step 2 – Model

1. Pre-train the spatial pattern encoder on WM811K (disjoint subset).
2. Train on the simulated Lots 1–4; **Lot 5 = test only** (lot-level split).
3. **Allowed inputs:** `parameter\\\_1–5`, x/y, Wafer-Test Fail map (and derived neighbor features). **Forbidden:** simulator risk map, coin flips, clue flags, cluster masks.
4. Output: risk score 0–1 for every passing die in Lot 5, giving a model risk map per wafer.

### Step 3 – Screening

Fixed threshold (not learned); dies ≥ threshold are sent to burn-in. Sweep the threshold on the same trained model.

### Step 4 – Evaluation

* Assume burn-in catches 100% of latent defects (no burn-in simulation needed).
* Metrics per threshold: % latent defects caught (recall), % **passing** dies burned in, escapes (DPPM), precision; plot the burn-in-fraction vs. recall curve.
* Example claim form: "At threshold 0.8, burning in 10% of passing dies caught 90% of latent defects."
* **Baselines:** random selection at the same burn-in %, distance-to-nearest-fail rule, neighbor z-score (residual) rule. The model must beat these.
* **Ablations/sensitivity:** no pre-training, weaker clues, fewer clued dies, weaker clustering multiplier.
* **Honesty rule:** the clue-planting mechanism should not be identical to a model feature; vary channels and shift sizes randomly.
* Business impact: translate burn-in % reduction into cost/cycle-time savings; translate escapes into DPPM.
* Failure modes to discuss: isolated unclued defects, near-full/random wafers, edge effects, simulator-assumption dependence.

## 9\. Proposal text (email-ready)

*As approved. Later changes: parametric data is now Gaussian on the KAI die grid (decision 17) and limits are mean ± 6σ (decision 19).*

Production burn-in catches latent defects: dies that pass wafer-level testing but fail early in the field. It is one of the most expensive and time-consuming steps in semiconductor test. Many manufacturers burn in every die, even though latent defects are rare and tend to cluster near visible wafer-level failures. This project asks whether a machine learning model can use wafer-level parametric data and spatial defect patterns to identify the small set of high-risk dies, so only those need burn-in. Wafer-test data matched to burn-in results is proprietary and not publicly available. We will therefore combine the KAI simulated analog wafer-test dataset (parametric values), real fab defect patterns from WM811K, and a seeded, configurable simulator that creates the hidden burn-in labels.
The simulator overlays WM811K defect patterns on KAI wafers. It turns a portion of each cluster into wafer-test failures by pushing values outside statistically derived limits (extreme percentiles of the measured data). It then gives each passing die a hidden probability of being latent defective, highest near clusters and fading with distance. A weighted coin flip picks about 1–2% of passing dies as latent defective. Most of these get faint parametric clues that stay inside the pass limits, and the rest get none, to stand for defects nothing could detect. Our model is pre-trained on WM811K patterns, trained on KAI Lots 1–4, and tested on Lot 5. It sees only what a real fab would have: parametric values, die positions and wafer-test fail locations. From these it produces a risk map for every wafer.
Dies above a set risk threshold are sent to burn-in, which we assume catches every latent defect. Sweeping the threshold lets us report trade-offs such as "caught 90% of latent defects while burning in only 10% of passing dies." The model will be compared against random selection, a simple distance-to-fail rule and a neighbor z-score rule. Ablations will cover pre-training, clue strength and clustering strength, and we will discuss failure modes such as isolated defects with no clue. The project follows the CRISP-DM framework and will be delivered as a GitHub repository with a Jupyter walkthrough and an interactive Gradio demo of the risk map and threshold trade-off.
